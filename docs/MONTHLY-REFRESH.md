# Monthly exception review

The customer-answer loop runs during normal support work; it does not wait for a monthly content project. The monthly pass exists only to find silent failures and accumulated exceptions.

## Start

```bash
./help
./help gap list --status open
./help gap list --status published
./help check --full
```

## Review primary sources

Check that each active source has produced fresh evidence or has a documented reason for silence:

- Freshdesk tickets and Drafter feedback events;
- help-page feedback;
- real site-wide search analytics, including zero-result queries;
- Telegram, WhatsApp, and support email threads used for customer support;
- current Shopify/product/operations facts when a gap depends on them.

Use exports and API responses as primary evidence. Old workshop corpora, audit reports, and model summaries may suggest where to look, but cannot verify a claim.

For each new reusable missing answer, record only a source reference and a privacy-safe description:

```bash
./help gap add --article /section/slug/ --missing "…" --source freshdesk --ref 1234
```

If there is no appropriate page, use the closest article temporarily and note that a new page or section is required. Do not invent a public answer to make the backlog look complete.

## Exception questions

1. Is any open high-risk gap waiting without an owner or authoritative source?
2. Did the same gap recur after publication?
3. Did a source go silent because collection broke?
4. Are multiple local checkouts splitting changes?
5. Do public claims disagree with current product, fulfillment, finance, safety, or legal reality?
6. Are published gaps still unobserved after a comparable outcome window?

## Finish

- Every new signal is linked to an existing gap or creates one.
- Every status move has a human evidence note.
- `./help check --full` passes.
- Published changes have a commit SHA and verified live URL.
- Private customer content remains outside git.

Do not create a second roadmap document. The private `BACKLOG.md` generated by `./help` is the view; `gaps.json` plus `events.jsonl` are the durable state and history.
